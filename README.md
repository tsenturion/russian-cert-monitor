# RussianCertMonitor

Локальное приложение для Windows: обнаруживает российские сертификаты, показывает основания классификации и позволяет вручную управлять чёрным списком Disallowed.

Приложение работает в трее. Проверяет все доступные зарегистрированные логические хранилища CurrentUser и LocalMachine, включая AuthRoot, Disallowed и нестандартные имена. По умолчанию опрос выполняется каждые 10 секунд. Обычная работа не требует сети и КриптоПро; приватные ключи не читаются, цепочки доверия не строятся.

## Возможности

- Список совпадений, полный инвентарь, чёрный список, ошибки чтения, справочник и история событий.
- Поиск по имени, владельцу, издателю, идентификатору, серийному номеру и расположению; фильтры категории и области.
- Структурированный разбор X.500/RDN: C=RU владельца и издателя, известные названия российских УЦ и идентификаторы из справочника. Кириллица и домен `.ru` сами по себе дают только косвенный признак.
- Объединение повторных отображений одного сертификата с сохранением всех наблюдаемых расположений. Учитываются просроченные и архивные записи.
- Уведомления о новых совпадениях и повторном появлении. Состояние сохраняется между запусками, неизменные совпадения повторно не уведомляют.
- Просмотр свойств, экспорт публичного CER, импорт одного публичного CER/CRT/PEM в Disallowed и удаление выбранной записи.
- Настройки интервала, уведомлений, дополнительных названий УЦ, идентификаторов российских сертификатов и исключений из уведомлений.
- История значимых событий и подтверждённых результатов ручных операций. Экспорт полного отчёта в JSON или читаемый TXT.

## Установка и запуск

Требуются Windows 10/11 x64 и Microsoft .NET Windows Desktop Runtime 10 x64. Обычная сборка представляет собой один EXE с использованием установленного runtime.

Распакуйте подготовленный дистрибутив и выполните PowerShell в его папке:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install_startup.ps1
```

Скрипт устанавливает и запускает `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\RussianCertMonitor.exe`. Двойной щелчок по значку трея или повторный запуск установленного EXE открывает окно работающего экземпляра. Закрытие окна возвращает его в трей; завершение — через «Выход» в меню значка.

Обновление выполняется той же командой. Скрипт останавливает только процесс из точного пути Startup, заменяет EXE и проверяет размер, версию и запуск установленной копии. Пользовательские данные хранятся отдельно и переживают обновление. Для удаления выйдите из приложения и удалите установленный EXE; записи Disallowed автоматически не меняются. Подробности — в [инструкции дистрибутива](Дистрибутив.md).

## Ручное управление Disallowed

Приложение изменяет сертификаты только после действия пользователя и подтверждения. Выберите сертификат или импортируйте один публичный файл, затем выберите CurrentUser либо LocalMachine. Для LocalMachine запускается короткий режим того же EXE через UAC с повторным подтверждением. Обмен между процессами проверяет PID обеих сторон.

Свежая проверка перед операцией и чтение результата после неё подтверждают наличие собственной записи в выбранной области. Логическая запись может оставаться видимой из-за наследования или политики Windows; это отображается отдельно. Удаление пользовательской записи не удаляет запись компьютера. Root, CA и групповые политики не изменяются. Удаление из Disallowed само по себе не устанавливает доверие.

Принимается ровно один публичный DER или PEM CERTIFICATE размером до 1 МиБ. PFX, приватные ключи и наборы сертификатов отклоняются. Нативное окно свойств открывается для просмотра с отключёнными установкой, редактированием и сетевым получением сертификатов. Экспорт CER выполняется отдельной кнопкой.

## Настройки и данные

Данные находятся в `%LOCALAPPDATA%\RussianCertMonitor`:

| Файл или папка | Назначение |
|---|---|
| `settings.json` | Интервал, уведомления и пользовательские правила |
| `monitor-state.json` | Последний сохранённый публичный снимок и состояние обнаружений |
| `certificate-history-catalog.json` | Необязательный локальный справочник ранее удалённых сертификатов |
| `History` | История значимых событий в JSONL |
| `Logs` | Диагностические журналы в JSONL |

Форма настроек применяет параметры после успешного сохранения и запускает новую проверку. Ручное редактирование JSON подхватывается при следующем запуске. Неверные, неизвестные или повторяющиеся поля вызывают предупреждение; повреждённый файл не перезаписывается при чтении. Ошибка записи сохраняет прежние действующие параметры.

```json
{
  "schemaVersion": 1,
  "pollIntervalSeconds": 10,
  "notificationsEnabled": true,
  "authorityNames": [],
  "russianCertificateIds": [],
  "notificationExclusions": []
}
```

Интервал — 5–3600 секунд. `authorityNames` содержит дополнительные названия УЦ для совпадения по границам слов с CN/O владельца или издателя. `russianCertificateIds` явно помечает выбранные пользователем идентификаторы как российские. `notificationExclusions` подавляет уведомления, сохраняя обнаружение, классификацию и ручное управление. В каждом списке не более 500 значений; идентификатор — 40 шестнадцатеричных символов.

Отключение уведомлений не останавливает мониторинг. После включения уже обнаруженное неизменное совпадение повторно не всплывает. Отмена пользовательского правила отличается в истории от исчезновения самого сертификата.

Публичный встроенный справочник содержит сведения об УЦ, без истории действий конкретного компьютера. Необязательный локальный справочник имеет ту же структуру списка `certificates` и `schemaVersion: 1`; записи из него дополнительно отмечаются как ранее удалённые. Он не включается в репозиторий или дистрибутив. Неизвестная принадлежность сохраняется как неизвестная.

История и диагностические журналы хранятся между запусками не более 30 дней. Удаляются только собственные файлы с распознанными именами при запуске и каждый час. Неизменные циклы не заполняют историю. Показываются последние 1000 событий с пределом чтения 4 МиБ; ограничения и ошибки обозначаются явно. Текущие настройки, состояние и сохранённые пользователем отчёты не являются журналами.

Экспорт отчёта сначала запускает проверку и сохраняет весь доступный инвентарь, настройки, историю и ошибки. Фильтры таблицы не ограничивают отчёт. Неполный снимок и предыдущие данные после сбоя обозначаются явно. В отчёт не включаются DER и приватные ключи.

## Границы проверки

Признаки принадлежности не доказывают вредоносность. CurrentUser может наследовать записи LocalMachine и не означает вторую независимую установку. Disallowed относится к проверке доверия средствами Windows; отдельные хранилища Firefox, Java, контейнеров и других пользователей не проверяются.

Ошибка доступа даёт статус неполной проверки, а не утверждение об отсутствии сертификатов. Неполный снимок может добавить реально наблюдаемое совпадение, но не подтверждает исчезновение прежней записи или снятие Disallowed. Появление и удаление между двумя опросами может остаться незамеченным. Показ уведомлений зависит от настроек Windows.

## Сборка и проверки

Для разработки нужен .NET SDK из `global.json`. Из корня репозитория:

```powershell
dotnet restore .\tests\RussianCertMonitor.Tests\RussianCertMonitor.Tests.csproj
dotnet build .\tests\RussianCertMonitor.Tests\RussianCertMonitor.Tests.csproj -c Release --no-restore
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_exe.ps1
```

Результат — `dist\RussianCertMonitor.exe`. Автономная упаковка доступна через `build_exe.ps1 -SelfContained` и может потребовать загрузки runtime; выполняйте её отдельно при необходимости.

Запускайте проверки только затронутой части:

| Маршрут тестового проекта | Область |
|---|---|
| `--catalog` | Публичный справочник, объединение и ошибки локальной истории |
| `--logging` | Отказ и восстановление диагностического журнала |
| `--stage2` | Классификация и инвентарь на тестовых данных |
| `--stage3` | Детектор изменений, сохранение, перезапуск и уведомления |
| `--stage4` | Публичные файлы, Disallowed, интерфейс и протокол UAC |
| `--stage5` | Настройки, правила, история, отчёты и интерфейс |
| `--stage6` | Живые интеграции с изолированным тестовым сертификатом CurrentUser Disallowed |
| `--inventory` | Только чтение живого инвентаря, результат JSON |

Например: `dotnet run --project .\tests\RussianCertMonitor.Tests -c Release --no-build -- --catalog`. Маршруты до этапа 6 не изменяют настоящие хранилища. Интеграции этапа 6 используют публичный тестовый сертификат C=US и удаляют его в `finally`; Root и CA не изменяются. Синтетический ГОСТ-пример проверяет только чтение метаданных, а не действительность подписи.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\verify_release.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\package_release.ps1 -SkipVerification
powershell -NoProfile -ExecutionPolicy Bypass -File .\install_startup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\verify_startup.ps1
```

`verify_release.ps1` сопоставляет инвентарь с независимым чтением PowerShell. `package_release.ps1` по умолчанию выполняет проверку перед сборкой; `-SkipVerification` использует сохранённый успешный результат для той же версии. Архив содержит EXE, установщик и инструкцию. Упаковка не публикует GitHub Release.

`verify_startup.ps1` проверяет установленный путь, перезапуск, второй экземпляр, окно, периодические циклы и защиту административного режима. При интервале выше 30 секунд периодические циклы помечаются непроверенными. Итоговый экземпляр остаётся запущенным в трее.

Из PowerShell администратора отдельно можно выполнить `verify_disallowed_admin.ps1 -VerifyOffline`: изолированная проверка LocalMachine и временная блокировка исходящей сети только для установленного EXE. Тестовые записи и собственное правило удаляются в `finally`. Нужен включённый брандмауэр и интервал 5–30 секунд. Результаты находятся в игнорируемой папке `work\release-checks`.

GitHub Actions выполняет целевые проверки справочника и интеграций на Windows и сохраняет ZIP как артефакт сборки. Дополнительные сведения — в [инструкции разработки](CONTRIBUTING.md) и [списке изменений](CHANGELOG.md).
